Before doing this research,I used to think about AI in software engineering mostly as a tool that helps people write code faster. I knew about tools like GitHub Copilot, but I did not think deeply about how companies actually use AI inside their real workflows. After researching these case studies,my opinion became more balanced. I still think AI is a powerful advantage for software engineers, but I also understand better that it can create problems if it is used without control.

What surprised me most was that big companies do not use AI only as a simple chatbot. For example, Shopify is building structured AI workflows and internal systems, while Google uses AI in a large engineering environment where code review, testing, documentation, and maintenance are all important. This showed me that professional AI use is not just “ask AI to write code.” It is more about building a controlled process where AI helps, but humans still guide and verify the result.

My biggest concern is that developers, especially beginners, may become too dependent on AI. If someone accepts AI-generated code without understanding it, they may finish tasks faster in the short term, but they will not build real problem-solving skills. This can become dangerous because AI can produce code that looks correct but still contains bugs, security issues, or bad design. In software engineering, a mistake is not always obvious immediately. Sometimes bad code creates technical debt that becomes a bigger problem later.At the same time, I see many opportunities. AI can save time on repetitive tasks, help explain unfamiliar code, generate tests, and support documentation. I think this can make software engineers more productive if they use it correctly. Instead of spending too much time on small mechanical tasks, engineers can focus more on architecture, logic, user needs and long term quality.

The skills that will remain important are critical thinking, debugging, testing, system design, communication, and responsibility. AI can generate suggestions, but it cannot fully understand the business goal, the users, the team situation, or the long-term consequences in the same way a good engineer can. Because of that, I think human judgment will become even more valuable.

Personally, this research made me realize that I should not try to avoid AI, but I also should not trust it blindly. I need to learn how to use AI as an assistant, not as a replacement for my own thinking. In the future, I want to improve my programming fundamentals, understand how systems work, and use AI to support my learning and productivity. My conclusion is that the best software engineers will not be the ones who ignore AI or depend on it completely. The best engineers will be the ones who know how to use AI carefully, check its output, and still think like real engineers.
